Schema reference

Version 1.0.0 is the only schema the editor reads. The file is packages/scene-schema/src/schema/venue.schema.json (JSON Schema draft 2020-12). Lengths are metres.

Document

A document requires schemaVersion, project, coordinateSystem, assets, and venue.

  • Every entity id is a UUID.
  • Names are 1 to 200 characters.
  • Unknown properties are kept on save. Do not rebuild the object field by field.
  • A file larger than five million characters, nested deeper than 32 levels, or carrying __proto__, constructor, or prototype is rejected before it loads.

Coordinates

v1 stores one coordinate system: metres, +Y up, right-handed, radians. Plan points are {x, z} because Y is up. On the plan, +X is to the right and +Z is up the screen.

Floors, rooms, and walls

A floor has a level, an elevation, and a floor-to-floor height. Level 0 is the ground. Rooms and walls live on a floor. A wall runs from start to end and has a thickness and a height. An opening is a door, a window, or an opening, placed by its offset from the wall start.

Objects and zones

An object is generic, stage, chair, table, booth, screen, podium, sign, or custom. Its position and rotation are in the transform. If assetId is set, that id must exist in assets.

A zone is a named area. Its interaction may be info-panel, link, menu, session-list, or none. The menu itself is a contentRef outside this file, so changing a menu does not require a venue migration.

What this version does not edit

Map can show every floor. The plan tools and the stairs still use the ground floor. Spawn points mark where a visitor starts. Optional navigation holds walkable areas for a later viewer.

How to add a later version is written in packages/scene-schema/MIGRATION.md.
